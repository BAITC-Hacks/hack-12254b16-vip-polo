# Игровой интерфейс — участник 1

База ветки feat/game-ui: 1127f02554ea2239f5ef680b36035767fe5efb70, объединённый каркас. Работа ведётся в отдельном клоне. Стек, зависимости, shared-контракт, JSON и чужие модули не менялись.

## Реализовано

GameShell содержит брифинг, исходный бюджет, прогресс пяти решений, переключение направлений, план и действия завершения/повтора. CityMap рисует три условных района в SVG: мышь, Tab + Enter/пробел, aria-pressed и видимый фокус. Под картой — исходные показатели и preview из общего расчёта. InitiativePicker читает переданный каталог, показывает стоимость, описание, эффекты, выбор и отмену. CSS Modules адаптируют интерфейс для мобильного экрана, без внешних шрифтов и изображений.

Состояние и запросы находятся в useGame.ts. Изменение плана отправляет целый кандидат в simulateScenario(..., 'draft'). Бюджетная ошибка сохраняет прежний план; успешная замена снимает предыдущее решение в этом направлении. Карточки не запрещают замену по старому remainingBudget: решение принимает общий расчёт. Формулы, суммы расходов и Score в UI не дублируются.

Завершение предварительно проверяется тем же модулем в final-режиме, затем POST /api/simulate получает только версии и решения. Ответ проверяется общей runtime-схемой, complete, scenarioId, версиями и идентичностью набора решений. Расчёт появляется сразу, после чего один раз вызывается /api/analysis. Анализ проверяется отдельно, включая идентичность обоих вложенных объектов; его расчёт не заменяет уже показанный результат. Ошибка AI сохраняет результат, повтор вызывает только /api/analysis. ResultsPanel подключён с исходными props; реализация панели остаётся у участника 3.

При правке решения, редактировании или повторе игры локальная revision увеличивается, AbortController отменяется, результат и анализ очищаются. Каждый сетевой запрос также получает отдельную revision; перед изменением состояния проверяются revision, активный контроллер и сигнал отмены. Защита работает даже если fetch фактически не остановился или пользователь вернулся к прежнему scenarioId. При unmount запрос отменяется. Повторные одновременные завершения/AI-запросы блокируются.

## Пока расчёт не подключён

Изменение modelVersion или datasetVersion в серверном GameData создаёт новую игровую сессию: прежнее состояние сбрасывается и старые запросы отменяются. Это также проверено отдельным тестом.

NOT_IMPLEMENTED допускает только явно непроверенный черновик: район, выбор, замену и отмену можно попробовать. Остаток и Score показаны прочерками, завершение заблокировано, видимо предупреждение. Даже пять выбранных карточек не выдаются за валидный сценарий. Нет runtime-импортов fixtures, вычислений вместо движка или поддельных API-ответов.

JSON содержит стартовые названия/описания участника 2; UI отображает их без собственного каталога. ResultsPanel, simulation и AI в базовой main остаются заглушками. Полное прохождение на этой ветке пока недоступно.

## Проверки

pnpm install --frozen-lockfile; pnpm lint; pnpm typecheck; pnpm test; pnpm build. Браузерная проверка: pnpm exec playwright install chromium, затем pnpm test:e2e. E2E запускает свой production-сервер на 3100; этот порт должен быть свободен. Для обычного просмотра — pnpm dev --port 3000.

tests/game/useGame.test.tsx проверяет контейнер с тестовыми ответами порта: A/B, замену при нулевом остатке, бюджетный отказ, отмену, неполный сценарий, исходный request, немедленный результат, ошибку/повтор/fallback AI, unmount, устаревшие успехи и ошибки, несовпадение ID/версий/решений, форму ответа и отказ сервера. Эти тесты не подтверждают реализацию движка или провайдера.

tests/game/interface.test.tsx проверяет клавиатуру карты, доступность замены и сборку/перенос/отмену/сброс черновика. Существующий тест страницы обновлён под честное состояние нового UI. Браузерный e2e проверяет реальный черновик, замену, отмену, клавиатуру и отсутствие горизонтального скролла на 390 px. Общие проверки API-заглушек сохранены до merge владельцев.

## Личная демонстрация

1. На карте выбрать Центральный с клавиатуры. Выбрать базовое мероприятие, заменить расширенным: в плане остаётся одна строка.
2. Выбрать Южный и мероприятие того же направления: строка перемещается, а не дублируется. Удалить её и начать заново.
3. На каркасе показать предупреждение, прочерки и недоступность завершения. Не демонстрировать это как работающую модель.
4. После merge simulation собрать A, заменить transport на premium (B), вернуть basic (A), удалить service (E). Завершение доступно только для полного допустимого сценария.
5. После подключения API при ожидающем ответе изменить решение, затем вернуть его: старый ответ не появляется. Контролируемое воспроизведение этой гонки без AI-ключа уже есть в tests/game/useGame.test.tsx.
