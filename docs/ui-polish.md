# Проверка приложения и улучшения интерфейса

Работа выполнена по отдельному запросу пользователя об улучшении приложения. Ветка `feat/app-polish` начинается от PR №3, `5fd66331fe20e51f8ecd9fb3d72ecc942d7ed9c1`. Опубликованные ветки участников сохранены, PR не объединялись. Для совместной проверки использована отдельная локальная копия с расчётным модулем PR №2. Этот PR содержит только дополнения интерфейса, его тесты и этот документ; для работающего расчёта при интеграции нужен PR №2.

## Поведение

- Карточки сразу показывают положительные и отрицательные эффекты из каталога. Развёрнутые описания доступны по запросу.
- Каждый кандидат передаётся общему `simulateScenario(..., 'draft')` вместе с новым полным набором решений, без старого решения этого направления. UI показывает полученный остаток бюджета и блокирует недопустимый вариант. Нулевой текущий остаток сам по себе не запрещает замену или перенос.
- План показывает стоимость каждого решения и позволяет вернуться к его району/направлению. Кнопка следующего направления помогает заполнить оставшиеся решения.
- Бюджетная полоса, изменение Score относительно baseline и отметка серверной проверки различают preview и завершённый сценарий.
- После завершения фокус переходит на заголовок результата. ResultsPanel показывает переданные Score, бюджет, городские и районные показатели. Раскрываемый разбор показывает каждый вклад правила, rawAfter, clampAdjustment и итог; повторного расчёта или отдельной формулы в ResultsPanel нет.
- AI-загрузка и ошибка не скрывают результат. Полученное объяснение проверяется схемой, идентификатором сценария, версиями и существованием factIds. Fallback явно обозначается. Сервер AI в текущем репозитории остаётся заглушкой; работающий AI не заявляется.
- Селекторы UI-тестов берут названия по стабильным ID каталога, поэтому текстовое наполнение данных PR №2 их не ломает.

Контракт, числовые данные, версии, fixtures, зависимости, глобальные стили и общие стартовые тесты не изменены. Отдельная правка типизации POST принадлежит PR №2.

## Воспроизведение

Node 24.19.0, pnpm 11.19.0; `pnpm install --frozen-lockfile`, затем `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm test:e2e`. На ветке от PR №3 расчёт ещё является заглушкой: её полный набор тестов проверяет именно эту базу и UI через портовые ответы неизменных fixtures. Реальное прохождение проверяется после локального подключения PR №2.

## Фактические проверки 23.09.2026

- Отдельная ветка поверх PR №3: lint, typecheck, стандартный production build (Turbopack), полный pnpm test — 56/56; существующий pnpm test:e2e — 2/2 (проверки базы с заглушкой расчёта).
- Объединённая локальная копия с PR №2: lint, typecheck и стандартный production build прошли; полный pnpm test — 146 passed / 2 failed. Падают только старые ожидания tests/contracts/page.test.tsx и scaffold.test.ts. Существующий e2e — 2 failed по старым ожиданиям недоступного расчёта и API 501.
- В отдельной проверке реальной связки hook + модель + маршруты + GameShell прошли 9/9 тестов: draft, A–E, замена при нулевом остатке, отклонение без мутаций, отмена, A→B→A, версии/ID/schema, финальный API, 120 перестановок.
- 92/92 теста расчётного модуля и 17/17 прямых запросов production API прошли. Score A/B/C: 51.67 / 52.53 / 53.33; D отклонён с 422; подменённые числа отклонены с 400.
- В браузере проверены карточки, переходы, завершение плана basic (51.67), отображение результата при ошибке AI, фокус заголовка и отсутствие горизонтального переполнения при ширине 390 px. Live AI не проверен и пока отсутствует.

Первый запуск в демонстрационной копии использовал ссылку node_modules на другой каталог: Turbopack отказался собирать такую файловую структуру, pnpm пытался автоматически переустановить зависимости. После самостоятельной установки `pnpm install --offline --frozen-lockfile` в каждой проверяемой копии обычные команды выполнены без обходов. Версии и lockfile не менялись.

## Действия координатора

Общие тесты после подключения модели требуют последовательного обновления:

1. tests/contracts/scaffold.test.ts: успешные validateScenario(A) и полный Outcome simulateScenario(A) вместо NOT_IMPLEMENTED; simulate API A → 200, D → 422, {} → 400. Проверки analysis и AI-помощников сохранить как заглушки до появления реализации.
2. tests/contracts/page.test.tsx: начальный preview со Score 50, бюджетом 100 и недоступным завершением пустого плана вместо сообщения об отсутствии расчёта.
3. tests/e2e/scaffold.spec.ts: реальное прохождение A, замена на B и обратно, отмена, завершение, отображение результата при ошибке AI, мобильная ширина; разделить ожидания simulate и analysis.

Патч этих общих проверок подготовлен отдельно для Талгата и в эту ветку не применялся. Красный общий прогон объединённой копии нельзя называть исправленным до применения и проверки этого изменения. GitHub Actions проверяется отдельно: у PR №2/№3 на момент аудита verify завершался до запуска шагов; локальные проверки не заменяют CI. Настройка защиты main и доступность Actions остаются у владельца репозитория.
