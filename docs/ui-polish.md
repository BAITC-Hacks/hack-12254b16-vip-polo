Отдельная ветка `feat/app-polish` основана на PR №3 (`5fd6633`). Её PR направлен в `feat/game-ui`, чтобы показать только дополнения к интерфейсу. `main` и опубликованные ветки участников не объединялись. Для полного приложения нужны PR №2 (`eb5418b`, расчёт), №3 и №4 (`eff459c0`, AI/results).

Во время работы опубликован PR №4. Итоговая версия сохраняет его ResultsPanel целиком: в diff относительно PR №3 нет файлов `src/features/results/**`, `src/lib/ai/**`, `src/app/api/analysis/**` или `tests/results/**`. Подробный разбор добавлен отдельно в `src/features/game/ScenarioTrace.tsx`. Дубли внешних кнопок редактирования/анализа и AI-статуса из GameShell убраны; callbacks панели сохранены.

## Поведение

- Карточки сразу показывают положительные и отрицательные эффекты каталога; развёрнутые описания раскрываются по запросу.
- Каждый кандидат передаётся общему `simulateScenario(..., 'draft')` вместе с новым полным набором решений, без старого решения этого направления. UI показывает полученный остаток и запрещает недопустимый вариант. Нулевой текущий остаток сам по себе не запрещает замену или перенос.
- План показывает стоимость решения, позволяет вернуться к его району и направлению. Следующий шаг ведёт к ещё не заполненному направлению.
- Полоса расхода, изменение Score относительно baseline и отметка серверной проверки различают preview и итог.
- После завершения фокус переходит на заголовок результата. ScenarioTrace показывает переданные городские показатели и разбор всех 15 районных показателей: baseline, каждый ruleId и вклад, rawAfter, clampAdjustment, after. Названия и объяснения берутся из переданного каталога. Собственной формулы Score или повторного расчёта внутри компонента нет. Таблицы районов ResultsPanel не дублируются.
- UI-тесты берут названия инициатив по стабильным ID. GameShell проверяется через тестовые порты; реальная связка проверяется отдельно. Runtime не импортирует fixtures.

Контракт, числовые данные, версии, fixtures, зависимости, глобальные стили и общие стартовые тесты не изменены.

## Воспроизведение

Node 24.19.0, pnpm 11.19.0; `pnpm install --frozen-lockfile`, затем `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm test:e2e`. Ветка от PR №3 ещё содержит заглушки движка/AI: для реального прохождения нужна локальная интеграционная копия всех трёх модулей. PR автоматически не объединяются.

Первая демонстрационная копия использовала ссылку node_modules на другой каталог, которую Turbopack не поддержал. После установки зависимостей через `pnpm install --offline --frozen-lockfile` обычные команды сборки выполнялись без обходов; lockfile сохранён.
